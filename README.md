# インソール計測アプリ（4センサー版）

スマートフォンから左右のマイコン（M5StickC Plus、ファームウェアは [insole_v1_measure2_4sensor](https://github.com/insole-project-KUARLab/insole_v1_measure2_4sensor) の `src/main.cpp`）に Bluetooth で接続し、センサーデータを記録するウェブアプリです。記録を止めると力のグラフを表示し、データ（CSV, PNG）を Google ドライブへ自動で保存します。計測中は、足型の上に荷重・せん断・COP をリアルタイムで表示することもできます。

**アプリを開く: https://insole-project-kuarlab.github.io/insole_v1_measure2_4sensor_app/**

このリポジトリは GitHub Pages で公開するため Public です。計測データ、被験者の情報、Google ドライブの URL や合言葉は入れないでください（ドライブの設定は各スマホの中にだけ保存されます）。

5センサー版のアプリ（`insole-measure_app`）をもとに、このシステムに合わせて作り直したものです。

| | 5センサー版アプリ | このアプリ |
|---|---|---|
| センサー | 5個 × 4コイル | 4個 × 4コイル（I2C 0x2A〜0x2D） |
| 受信するパケット | 旧形式（0x00 / 0x11、1 nH 単位） | v3（0xB1）と v2（0xA1 / 0xA2）、0.1 nH 単位 |
| CSV | ヘッダーあり、21列 | ヘッダーなし、17列（`insole_live_collect_plot.py` と同じ） |
| ファイル名 | `L_27.5cm_S0007_corridor3rd.csv` | `data_left_18.5cm_S0001_walk1_insole_L_7780_20261112_175757.csv` |
| 左右の選択 | 一覧に左右とも同じ名前で出る | 「左足に接続」では insole_L_… だけが出る |
| 切断されたとき | 手動でつなぎ直す | 自動で再接続し、記録を続ける |
| 力の計算 | force_data_processor.py | foot_view.py と同じ式（Fx・Fy・Fz、単位は nH） |

## 使えるブラウザ

- Android: Chrome
- iPhone: Bluefy（Safari や iPhone の Chrome は Web Bluetooth に対応していません）

Web Bluetooth は **https** のページでしか使えません。このリポジトリは GitHub Pages（main ブランチの直下）で公開していて、main に push すると1〜2分で上の URL に反映されます（PC で試すときは `http://localhost` でも動きます）。5センサー版と同じサイトに置いても、設定・未送信データ・キャッシュは混ざりません。

## 使い方

1. **計測情報を入力する**
   - サイズ（cm）：例 `18.5`
   - 被験者 ID：例 `S0001`（入力した ID は次から候補に出ます）
   - 実験名：英数字で入力（例 `walk`）。ファイル名には試行回数を付けて `walk1`、`walk2` … となります
   - 試行回数：記録を止めるたびに1つ増えます。サイズ・被験者・実験名を変えると 1 に戻ります
2. **マイコンを接続する**
   本体の電源を入れ、「左足に接続」「右足に接続」を押して一覧から選びます。本体の画面の `SIDE` が左右と合っているか確認してください（合っていないと警告が出ます。正面のボタンを約1.2秒押すと切り替わります）。
3. **記録する**
   「記録開始」を押すと記録が始まり、もう一度押すと止まります。記録中は画面を消さないでください。
4. **結果を確認する**
   止めると力のグラフが表示され、データが Google ドライブにアップロードされます。「CSV を共有」「画像を共有」から、スマホへの保存やメール送信もできます。

各足のカードには、受信レート（本来は約 40 Hz）、パケット形式、欠けたサンプル数が表示されます。

- **形式**：iPhone（Bluefy）では通常 `v3`、Android の Chrome では `v2` になります。どちらでもデータは同じです。v3 は1回分の通知を取りこぼしても次の通知で補えます（「補完」の数）。
- **欠け**：補えずに欠けたサンプル数です。
- **センサーエラー**：本体が LDC との通信に失敗しているときに赤字で表示されます。エラーになったコイルは CSV では `nan` になります。

## 足型ビュー

「足型ビュー」を開くと、計測リポジトリの `script/foot_view.py` と同じ内容をスマホに表示します。

| 表示 | 意味 |
|---|---|
| 足型の色（青） | 各センサーの Fz（4コイルの ΔL の合計）をなだらかに広げたもの（σ = 18 mm）。濃いほど荷重が大きい |
| 細い円 | センサーの位置と大きさ |
| 黒い矢印 | せん断（Fx は体の内側、Fy は前が正）。1000 nH で 30 mm |
| オレンジの点と線 | COP と直近約1秒の軌跡 |

- **ゼロ点**：接続直後の1秒間の平均です。足を乗せずに接続してください。乗せたまま接続したときは、両足を浮かせて「ゼロ点を取り直す」を押します。
- **色が一番濃くなる Fz**：初期値は foot_view.py と同じ 3500 nH です。色の変化が小さいときは下げてください。
- **荷重による L の変化の向き**：初期値は foot_view.py と同じ「ΔL をそのまま使う」です。足を乗せても色が付かないときは「L が減る」に切り替えてください。力のグラフにも同じ設定が使われます。
- 足型は計測リポジトリの `script/geometry/insole_18.5cm_4sensor.json` を `geometry.js` に写したものです。サイズを変えるときは、`make_foot_geometry.py` で作った JSON の中身で `geometry.js` の `self.INSOLE_GEOMETRY = …` を置き換えてください。

## 力のグラフ

記録を止めたとき、または「CSV を読み込む」で保存済みの CSV（このアプリや `insole_live_collect_plot.py` の CSV）を選んだときに表示されます。

- 値はセンサーごとの ΔL（nH、キャリブレーション前）から foot_view.py と同じ式で計算した Fx・Fy・Fz です。
- ローパスフィルタ（5センサー版アプリと同じ係数の filtfilt）をかけています。
- ゼロ点は記録開始直後の1秒の平均です。
- 横軸は本体の `timestamp_ms` です。

## CSV

`insole_live_collect_plot.py` と同じ形式です。そのまま `script/data` に入れて解析できます。

```
data_<left|right>_[サイズ]_[被験者]_[実験名+試行回数]_<BLE名>_<開始日時>.csv
例: data_left_18.5cm_S0001_walk1_insole_L_7780_20261112_175757.csv
```

- ヘッダーなし、17列（`timestamp_ms, s1c1, s1c2, s1c3, s1c4, s2c1, …, s4c4`）
- 値はインダクタンス（nH、小数1桁）。センサーエラーは `nan`
- 開始日時は左右で共通（「記録開始」を押した時刻）
- 受信済みのサンプル（時刻が前回以下）は保存しません

## Google ドライブへの保存

5センサー版アプリと同じ Apps Script の受け口をそのまま使えます。アプリの「Google ドライブ」→「送信先の設定」に、ウェブアプリの URL と合言葉を入れて「接続を確認」を押してください。

```
（保存先フォルダ）
└ 20261112            ← 記録した日付
   └ S0001            ← 被験者 ID
      ├ csv
      │  ├ data_left_18.5cm_S0001_walk1_insole_L_7780_20261112_175757.csv
      │  └ data_right_18.5cm_S0001_walk1_insole_R_7430_20261112_175757.csv
      └ png
         ├ data_left_18.5cm_S0001_walk1_insole_L_7780_20261112_175757.png
         └ data_right_18.5cm_S0001_walk1_insole_R_7430_20261112_175757.png
```

電波がない場所で記録を止めたときは、データはスマホ内に残り、「未送信を再送」ボタンが出ます。電波が戻ったときやアプリを開き直したときにも自動で再送します。

受け口を新しく作るとき（初回のみ、PC で作業）：

1. Google ドライブに保存先フォルダを作り、URL の `/folders/` より後ろの英数字（フォルダ ID）を控えます。
2. [script.google.com](https://script.google.com) で新しいプロジェクトを作り、`apps_script.gs` の内容を貼り付けて、`FOLDER_ID` と `TOKEN`（合言葉）を書き換えて保存します。
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。「次のユーザーとして実行」を **自分**、「アクセスできるユーザー」を **全員** にしてデプロイし、承認します。
4. 表示された URL（`https://script.google.com/macros/s/…/exec`）をブラウザで開き、「受け口は動いています。保存先フォルダも見つかりました。」と出れば準備完了です。

Apps Script を書き換えたときは、「デプロイを管理」→ 鉛筆マーク →「新バージョン」でデプロイし直してください。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | アプリ本体（画面、BLE 接続、記録、グラフ、足型ビュー、アップロード） |
| `core.js` | 画面に依存しない処理（パケットの解読、CSV、力の計算） |
| `geometry.js` | 足型とセンサー位置 |
| `manifest.webmanifest` / `sw.js` | ホーム画面に追加したときの設定、オフライン起動 |
| `icon-192.png` / `icon-512.png` / `apple-touch-icon.png` | アイコン |
| `apps_script.gs` | Google ドライブの受け口（Apps Script） |
| `test/core.test.js` | `core.js` のテスト。`node test/core.test.js` で実行（計測リポジトリを隣のフォルダに置いておくと、その実データでも試します） |

アプリを更新したら、`sw.js` の `VERSION` を上げてください（上げないと、スマホに古い版が残ることがあります）。ファームウェアのパケット形式を変えたときは、`core.js` の `handlePacket` と `test/core.test.js` を合わせて直してください。

## 注意事項

- 記録中に画面を消したり、別のアプリに切り替えたりすると、記録が止まります。
- 左右の `timestamp_ms` は別々の本体の時計の値なので、そのまま引き算して比べることはできません。
- 5センサー版のファームウェアの本体には接続しても受信できません（「旧ファーム」と表示されます）。

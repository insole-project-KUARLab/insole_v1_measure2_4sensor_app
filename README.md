# インソール計測アプリ（4センサー版）

スマートフォンから左右のインソール（M5StickC Plus）に Bluetooth で接続し、センサーデータを記録するアプリです。記録を止めて「ドライブに送る」を選ぶとデータ（CSV・グラフ画像）を Google ドライブへ保存します。

**アプリを開く: https://insole-project-kuarlab.github.io/insole_v1_measure2_4sensor_app/**

被験者に自分のスマホで計測してもらうときの案内文は [subject_message.md](subject_message.md) にあります。

## 使えるスマホとブラウザ

| スマホ | ブラウザ |
|---|---|
| Android | Chrome |
| iPhone | [Bluefy](https://apps.apple.com/jp/app/bluefy-web-ble-browser/id1492822055)（リンクから App Store で入れる） |

iPhone の Safari や Chrome は Bluetooth に対応していないため使えません。

URL を開いたら、ブラウザのメニューから「ホーム画面に追加」をしておくと、次からアプリのように開けます。

## はじめての準備（スマホごとに1回）

### 合言葉を入力する

データは決まった Google ドライブのフォルダ（`insole_data`）に保存されます。送信先はアプリに設定済みなので、入力するのは合言葉だけです。

1. アプリの「Google ドライブ」→「合言葉の設定」を開きます（未入力のときは最初から開いています）。
2. 合言葉を入力します。研究室で共通の値です。分からなければ、管理している人に聞いてください。
3. 「接続を確認」を押して、「接続できました。」と出れば完了です。

合言葉はそのスマホの中にだけ保存されます。合言葉は、ドライブに知らない人がファイルを送り込めないようにするためのパスワードです。GitHub や公開の場所には書かないでください。

### インソールの左右を確認する

本体の電源を入れると、画面に左右の設定と名前が表示されます。

```
SIDE: LEFT
BLE : insole_L_7780     ← L が左足、R が右足。4桁は本体ごとの番号
```

左右が違うときは、本体の**正面のボタンを約1.2秒押し続ける**と切り替わります（再起動します）。

## 計測の手順

### 1. 計測情報を入力する

| 項目 | 例 | 説明 |
|---|---|---|
| サイズ（cm） | `18.5` | インソールのサイズ。0.5 刻み |
| 被験者 ID | `S0001` | 一度入れた ID は、次から候補に出ます |
| 実験名 | `walk` | 英数字で入力。ファイル名では試行回数が付いて `walk1`、`walk2` … になります |
| 試行回数 | `1` | 記録を「ドライブに送る」たびに自動で1つ増えます（破棄したときは増えません）。サイズ・被験者・実験名を変えると、その組み合わせの前回の続きの番号になります。日付が変わると 1 に戻ります（その日に初めての組み合わせも 1） |
| 今日の体重（kg） | `55.2` | その日に1回入力します。被験者 ID を先に入れてください |
| 着用していた靴の写真 | | 「靴の写真を撮る・選ぶ」を押して、カメラで撮るか写真を選びます。被験者 ID を先に入れてください |

入力欄の下に、次に保存されるファイル名が表示されます。

体重と靴の写真はファイル名や CSV には入りません。入力するとすぐに、管理している人だけが見られる場所に送られます（[体重と靴の写真の記録](#体重と靴の写真の記録)）。

### 2. インソールを接続する

1. 左右のインソールの電源を入れます。**このとき、まだ足を乗せないでください**（接続直後の1秒間をゼロ点にするため）。
2. 「左足に接続」を押し、一覧から `insole_L_…` を選びます。
3. 「右足に接続」を押し、一覧から `insole_R_…` を選びます。

接続すると、各足のカードに波形が流れ始めます。受信が約 40 Hz になっていれば正常です。

### 3. 記録する

「記録開始」を押すと記録が始まり、もう一度押すと止まります。

- **記録中は画面を消したり、別のアプリに切り替えたりしないでください。** 記録が止まります。
- 途中で接続が切れても、自動でつなぎ直して記録を続けます。

### 4. 送るか破棄するかを選ぶ

記録を止めると、「記録開始」ボタンの下に次の2つのボタンが出ます。どちらかを押してください。

| ボタン | すること |
|---|---|
| ドライブに送る | CSV とグラフ画像（力のグラフ）を Google ドライブにアップロードし、試行回数を1つ増やす |
| 破棄する | 確認のあと、記録を捨てる。ドライブには送らず、試行回数もそのまま（同じ番号で取り直せる） |

- ボタンの上に、データに欠けがないかの確認結果が出ます。欠け（通信が途切れて取れなかった時間）、記録中の切断、センサーエラー、片足のデータがない、のどれかがあると赤い枠で知らせます。やり直すときは「破棄する」を押してください。
- どちらかを選ぶまで、次の「記録開始」は押せません。
- 選ぶ前にアプリを閉じると、その記録は消えます（破棄と同じ）。

続けて次の試行を記録するときは、そのまま「記録開始」を押してください。

## 画面の見かた

### 各足のカード

| 表示 | 意味 |
|---|---|
| 波形 | センサー S1〜S4 の変化量（各センサーの4コイルの合計から、接続直後の1秒の平均を引いたもの）。S1 がつま先側、S4 がかかと側。接続してから1秒間は「ゼロ点を取得中」と出ます |
| サンプル | 受信したサンプル数（記録中は記録した行数） |
| 受信 | 1秒あたりの受信数。約 40 Hz が正常 |
| 形式 | 通信の形式。iPhone では通常 `v3`、Android では `v2`。どちらでも保存されるデータは同じ |
| 欠け | 通信が途切れて取れなかったサンプル数。「補完」は、取りこぼしたが次の通信で取り戻せた数 |
| 赤字「センサーエラー」 | 本体がセンサーと通信できていない。ケーブルの接続を確認する |
| 橙字「本体は右足（左足）に設定されています」 | 左右を逆に接続している。正しい足に接続し直すか、本体の左右を切り替える |

### 足型ビュー

「足型ビュー」を開くと、足型の上に荷重の様子をリアルタイムで表示します。

| 表示 | 意味 |
|---|---|
| 青の濃さ | 荷重（Fz）の大きさ。濃いほど大きい。センサーの間の色は推定値 |
| 黒い矢印 | 横方向の力（せん断）。体の内側向き・前向きが正 |
| オレンジの点と線 | 圧力の中心（COP）と、直近約1秒の軌跡 |

- 足を乗せたまま接続してしまったときは、両足を浮かせて「ゼロ点を取り直す」を押してください。各足のカードの波形のゼロ点も取り直されます。
- 色の変化が小さいときは、「色が一番濃くなる Fz」の数字を小さくします（初期値は 200。例: 100）。
- 足を乗せても色が付かないときは、「荷重による L の変化の向き」を切り替えてください。この設定は波形と、ドライブに送るグラフ画像にも反映されます。
- 値はキャリブレーション前のインダクタンスの変化（nH）で、力の単位（N）ではありません。

## データの保存先

### ファイル名

```
data_<left|right>_<サイズ>_<被験者ID>_<実験名+試行回数>_<インソール名>_<開始日時>.csv
例: data_left_18.5cm_S0001_walk1_insole_L_7780_20261112_175757.csv
```

開始日時は「記録開始」を押した時刻で、左右で同じになります。グラフ画像は同じ名前の `.png` です（アプリの画面には出さず、ドライブにだけ保存します）。グラフ画像には X・Y・Z 方向それぞれについて、センサーごとの値と S1〜S4 の合計が描かれています。値はキャリブレーション前のインダクタンスの変化（nH）で、記録開始直後の1秒をゼロ点にしています。

### Google ドライブ

```
insole_data
└ 20261112            ← 記録した日付
   └ S0001            ← 被験者 ID
      ├ csv
      │  ├ data_left_…csv
      │  └ data_right_…csv
      └ png
         ├ data_left_…png
         └ data_right_…png
```

- 電波がない場所で「ドライブに送る」を押したときは、データはスマホ内に残り、「未送信を再送」ボタンが出ます。電波のある場所で押してください。電波が戻ったときやアプリを開き直したときにも自動で再送します。
- 同じ名前で中身の違うファイルがすでにあるときは、上書きせずに `_2` を付けて保存します。

### 体重と靴の写真の記録

体重と靴の写真は `insole_data` には保存しません。Apps Script をデプロイした人のマイドライブ（直下）に、次の2つを作って保存します。どちらも誰とも共有されないので、デプロイした人だけが見られます。

| 名前 | 種類 | 中身 |
|---|---|---|
| `insole_体重記録` | スプレッドシート | 1日・1被験者ごとに1行 |
| `insole_靴の写真` | フォルダ | 靴の写真。名前は `<日付>_<被験者ID>.jpg`（例: `20261114_S0001.jpg`） |

靴の写真を自分で作ったフォルダに入れたいときは、Apps Script の `SHOE_FOLDER_ID` にそのフォルダの ID（フォルダを開いたときの URL の `folders/` のあとの英数字）を書いて、新バージョンでデプロイし直します。空のままなら、上の `insole_靴の写真` を自動で作ります。共有しているフォルダ（`insole_data` など）を指定すると、ほかの人にも写真が見えるので注意してください。

スプレッドシートは次の形です。「靴の写真」の列の URL を開くと、その写真が見られます。

| 日付 | 被験者 ID | 体重 (kg) | 記録日時 | 靴の写真 |
|---|---|---|---|---|
| 2026/11/14 | S0001 | 55.2 | 2026/11/14 09:30:12 | https://drive.google.com/file/d/… |

- 最初に送られたときに、自動で作られます。
- 同じ日・同じ被験者 ID の体重を入れ直すと、その行を上書きします。写真を撮り直すと、前の写真はゴミ箱に移り、新しい写真に入れ替わります。
- 写真は長辺 1600 ピクセルの JPEG に縮めて送ります。
- 電波がないときは、CSV と同じように端末に残して、あとで自動で送ります。
- スマホには、その日の入力値と写真の小さな見本だけが残ります（日付が変わると消えます）。
- **このファイルやフォルダを共有したり、`insole_data` の中に移したりしないでください。** ほかの人にも見えるようになります。

### スマホに保存・送信する

「CSV を共有」から、スマホへの保存やメール・AirDrop での送信ができます。共有に対応していないブラウザでは、「左足をコピー」「右足をコピー」で CSV の中身をコピーできます。

### CSV の中身

ヘッダーなしの17列です。

```
timestamp_ms, s1c1, s1c2, s1c3, s1c4, s2c1, …, s4c4
```

| 列 | 内容 |
|---|---|
| `timestamp_ms` | インソール本体の時計（ms）。左右は別々の時計なので、そのまま比べることはできません |
| `sNcM` | センサー N・コイル M のインダクタンス（nH、小数1桁）。センサーエラーのときは `nan` |

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「Web Bluetooth に対応していません」と出る | Android は Chrome、iPhone は [Bluefy](https://apps.apple.com/jp/app/bluefy-web-ble-browser/id1492822055) で開く |
| 接続の一覧にインソールが出ない | 本体の電源と、画面の `SIDE` を確認する。それでも出なければ「計測情報」→「BLE 設定」で「左右を区別せずに…すべて一覧に表示」にチェックを入れる |
| 受信が 40 Hz より大きく下がる | スマホとインソールを近づける。一度切断して接続し直す |
| 「旧ファーム」と表示される | 本体に別のファームウェアが入っている。4センサー版のファームウェアを書き込み直す |
| アップロードできない | 電波を確認して「未送信を再送」を押す。「合言葉が一致しません」と出たら、「合言葉の設定」の合言葉を確認する |
| アプリの表示が古いまま | アプリを一度閉じて開き直す |

## アプリを修正する人へ

- このリポジトリは GitHub Pages で公開しているため Public です。計測データ、被験者の情報、合言葉、ドライブのフォルダの URL は入れないでください（Apps Script の URL は合言葉がないと使えないので、`index.html` に書いてあっても問題ありません）。
- main に push すると1〜2分で公開ページに反映されます。そのとき `sw.js` の `VERSION` の数字を上げてください（上げないと、スマホに古い版が残ることがあります）。
- 送信先の受け口（Apps Script）の URL は `index.html` の `DEFAULT_GD_URL` に書いてあります。保存先のフォルダは Apps Script 側の `FOLDER_ID` で決まります。
- 体重・靴の写真の保存には、`apps_script.gs` の新しい版（`saveShoe_` があるもの）が必要です。古い受け口のままだと、アプリに「体重・靴の写真の保存に対応していない古い版です」と出て、送れなかったものは端末に残ったままになります（CSV は送られます）。
- 受け口を新しく作るときは、`apps_script.gs` を [script.google.com](https://script.google.com) に貼り付け、`FOLDER_ID` と `TOKEN`（合言葉）を書き換えて、「ウェブアプリ」（実行するユーザー: 自分、アクセスできるユーザー: 全員）としてデプロイします。表示された URL で `DEFAULT_GD_URL` を書き換えてください。Apps Script を書き換えたときは、「デプロイを管理」→ 鉛筆マーク →「新バージョン」でデプロイし直します（URL は変わりません）。貼り直すときは、`FOLDER_ID` と `TOKEN` を元の値に書き換えるのを忘れないでください。体重・靴の写真の保存を初めて使うときは、エディタ上部の関数の選択欄で `setup` を選んで「実行」を押し、スプレッドシートを使う許可を出してください（デプロイし直すだけでは許可の画面が出ず、アプリに「SpreadsheetApp.create を呼び出す権限がありません」と出ます）。
- パケットの解読・CSV・力の計算は `core.js` にあり、`node test/core.test.js` でテストできます。
